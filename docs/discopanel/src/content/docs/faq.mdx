Answers to the questions that get asked over and over.

<details>
  <summary>How do I update Discopanel?</summary>

  <details>
    <summary>Docker Compose</summary>

In the folder where your `compose.yml` file is, run:

1. `docker compose down`
2. `docker pull nickheyer/discopanel`
3. `docker compose up -d`

  </details>

  <details>
    <summary>Proxmox Helper Script</summary>

Open the console for the container and enter `update`.

  </details>

  <details>
    <summary>Source</summary>

Download the new binary and run it.

<details>
  <summary>I'm using host networking but something is already on port 8080. How do I change the port?</summary>

If you're using `config.yaml`, set this option:

```yaml
server:
  port: "8080"
```

Or set the `DISCOPANEL_SERVER_PORT` environment variable to whatever port you want.

</details>

<details>
  <summary>How do I set up the proxy for my servers?</summary>

Enable the proxy in **Settings → Routing & Exposure**, add a listener port, and give each server a hostname under your base URL. Clients then connect to the shared listener and DiscoPanel routes them to the right server by hostname.

Two extra knobs worth knowing:

- **Fallback Server (Lobby)** — pick a server in Settings → Routing & Exposure. When someone connects to a hostname whose server is offline, they're routed to the fallback (a lobby, typically) instead of getting disconnected.
- **Connection Limit** — per server, on the server's Config tab. Caps how many proxied connections that server will accept (`0` = unlimited). Useful for keeping a lobby from soaking up every slot.

See the [Players, Whitelist & Bans guide](/guides/players-and-whitelist/) for how the proxy tracks players and traffic.

</details>

<details>
  <summary>Can DiscoPanel restart a server after it crashes?</summary>

Yes — every server has an **Auto-Restart** option on its Config tab. When the container exits unexpectedly (crashes, OOM, whatever), DiscoPanel restarts it automatically with exponential backoff:

- **Auto-Restart** — the on/off switch. User-initiated stops are never restarted.
- **Max Retries** — consecutive crash restarts before DiscoPanel gives up (`0` = keep trying).
- **Backoff (seconds)** — the base delay between restarts. It doubles with each consecutive crash (30s, 60s, 120s, …) and resets once the server stays up for a few minutes, so a genuinely broken server doesn't get hammered in a loop.

Pair it with [alert rules](/guides/metrics-and-alerts/) if you want to know when it happens.

</details>

<details>
  <summary>How do I reuse one server's setup for another server?</summary>

Save it as a template. On a server's Overview tab, open the menu and pick **Save as Template** — optionally including the server's mods directory. The **Templates** manager on the Servers page lists your saved templates, and deploying one creates a new server with the same configuration (and mods) ready to go.

</details>

<details>
  <summary>How do I update a modpack in place?</summary>

Open the server's **Modpack** tab. The world is preserved on every update:

1. **Check for updates** — shows the installed version and the latest available.
2. **List versions** — pick a specific version, or leave it on latest.
3. **Update Modpack** — with **Create pre-update backup** enabled (recommended), DiscoPanel backs up first, then updates. If anything goes wrong, hit **Rollback** to restore that pre-update backup (server must be stopped).

You can also automate it: **Enable Automatic Updates** on the same tab, set the **Check Interval (hours)** and an **Update Mode** — **Notify** just raises a *modpack update available* event (hook it to a webhook task to get pinged), while **Apply** backs up, stops the server, updates, and restarts on its own.

</details>

<details>
  <summary>Is there a quick way to jump between pages?</summary>

Press <kbd>Ctrl</kbd>+<kbd>K</kbd> (or <kbd>Cmd</kbd>+<kbd>K</kbd>) anywhere in the panel for the global search. There's also a **Quick Edit Config** option in the menu on a server's Overview tab for making small config-file edits without hunting through the Files tab.

</details>

<details>
  <summary>How do I back up my servers?</summary>

Create a **Backup** task in your server's Tasks tab. It archives your world data on a schedule (safely, even while the server is running) and prunes old backups based on the retention rules you set. See the [Server Backups guide](/guides/backups/) for full details, including how to restore.

</details>

<details>
  <summary>Why can't I change my RAM allocation in the server JVM config?</summary>

RAM maximums are adjusted via the Memory field in the overview section. It is done this way so that the minecraft docker container can have some amount of RAM available to handle all the other things it needs to do other than just run a minecraft server. The JVM allocation is then computed from the Memory value it is given to have enough space.

</details>

<details>
  <summary>Where do I find my logs?</summary>

In Settings → Logs.

</details>

<details>
  <summary>I'm using Simple Voice Chat or Square/Dynmap and I want to expose that port. How do I do that?</summary>

This is best done using the 'Additional Ports' section of the overview tab of the server you want to adjust. At current there is no reverse proxy built into Discopanel for these, but Simple Voice Chat does have its own implementation that you should check out.

</details>

<details>
  <summary>How do I stop Discopanel from updating my servers?</summary>

  <details>
    <summary>Curseforge</summary>

Jump to the Curseforge config options of the desired server and edit the `CF_URL`, `CF_FILE_ID`, or `CF_FILENAME_MATCHER` fields to pin a specific version.

For example, to pin ATM10 to v2.42:
- `CF_URL`: `https://www.curseforge.com/minecraft/modpacks/all-the-mods-10/files/6378501`
- `CF_FILE_ID`: `6378501`
- `CF_FILENAME_MATCHER`: `2.42`

More info in the [itzg/docker-minecraft docs](https://docker-minecraft-server.readthedocs.io/en/latest/).

  </details>

  <details>
    <summary>Modrinth</summary>

Refer to the [itzg/docker-minecraft docs](https://docker-minecraft-server.readthedocs.io/en/latest/types-and-platforms/mod-platforms/modrinth-modpacks/#modpack-version).

  </details>
</details>

<details>
  <summary>Discopanel keeps deleting the mods I upload. How do I stop it?</summary>

  <details>
    <summary>Curseforge</summary>

If you're uploading a new mod, you can do it via:

- A download repo via the `CF_DOWNLOADS_REPO` environment variable — just download the mods you want to that folder.
- The `CURSEFORGE_FILES` environment variable using the project ID and file ID for the mod you want.
  - For example, to add Distant Horizons v2.45-b, you would set `508933:7375285`.

Both options are configured in the **Docker Container Overrides** section of the Overview tab. They are not currently exposed in the normal config options but are useful nonetheless.

  </details>

  <details>
    <summary>Modrinth</summary>
    Check [here](https://docker-minecraft-server.readthedocs.io/en/latest/types-and-platforms/mod-platforms/modrinth-modpacks/).
  </details>
</details>

<details>
  <summary>Failed to start server: [failed_precondition] ... etc</summary>

This is usually a permissions issue. Discopanel runs Minecraft server containers as `PUID:GID 1000:1000` by default, so if that user/group doesn't have access to Discopanel's install directory, you'll hit this error. Use `ls -la` to check permissions, `chown` to change ownership, and `chmod` to adjust permissions.

</details>

<details>
  <summary>Issues related to Fuego, Curseforge API, or download errors in the server console</summary>

These are likely not something we can help with. Either your DNS isn't working properly, Curseforge's API is having issues, or your connection to Curseforge is otherwise blocked (e.g. by a firewall).

</details>

<details>
  <summary>My curseforge API key isn't working.</summary>

Sometimes it takes a day or two for the key to start working in Discopanel when it works fine via curl or Postman. Sometimes it helps remaking the key once or twice too.
</details>

<details>
  <summary>Discopanel ran out of memory or failed when uploading a file</summary>

Try uploading the file using `scp` or `ftp` to move it directly into the folder it needs to be in.

**Make sure the file has the right permissions so Discopanel can read and write to it.**

</details>
